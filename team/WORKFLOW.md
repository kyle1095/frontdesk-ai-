## Default Process
1. Members push code to feature branches and create pull requests
2. The team lead reviews and merges PRs
3. Before starting new work, members should pull the latest default branch so they branch from up-to-date code

## Session budget rule (multi-part builds)
Work sessions have a finite budget and can end without a final report. On any build expected to take more than a few edits:
- Commit and push to the feature branch **incrementally** after each completed piece — never hold everything uncommitted
- Open a **draft PR early** (within the first third of the session) and keep it updated
- An interrupted session must leave a recoverable trail, not a dirty tree
